## Bugs Fixed

### 1. Advanced Indicators Not Computed (CRITICAL)

**File:** `simulator/indicator_base.py`

**Problem:** The `precompute_all_indicators()` function only handled basic indicators (sma, ema, rsi, macd, etc.) but NOT advanced indicators like `adx`, `supertrend`, `vwap`, `mfi`, `obv`.

**Impact:** Strategies requiring advanced indicators received NaN values and couldn't generate signals.

**Fix:** Added handling for advanced indicators in `precompute_all_indicators()`:
```python
# Added cases for advanced indicators
elif indicator_name == 'vwap' and ADVANCED_INDICATORS_AVAILABLE:
    enriched_data['vwap'] = calculate_vwap(data)
elif indicator_name == 'adx' and ADVANCED_INDICATORS_AVAILABLE:
    adx_vals, plus_di, minus_di = calculate_adx(data, period)
    enriched_data['adx'] = adx_vals
    enriched_data['adx_plus_di'] = plus_di
    enriched_data['adx_minus_di'] = minus_di
# ... etc for supertrend, mfi, obv
```

### 2. EMA Period Parsing Bug (CRITICAL)

**File:** `simulator/indicator_base.py`

**Problem:** When parsing indicator specs like `ema_20`, the code incorrectly extracted the period:
```python
# Bug: Was using parts[0] which is 'ema', not '20'
params['period'] = int(parts[0])  # WRONG
```

**Impact:** Both `ema_20` and `ema_50` were computed with default period of 20, making EMA20 == EMA50 always, so strategies couldn't detect trend alignment.

**Fix:**
```python
# Fixed: Use parts[1] for the period
params['period'] = int(parts[1])  # CORRECT
```

### 3. Compound Indicator Names Not Parsed

**File:** `simulator/indicator_base.py`

**Problem:** Indicators with underscores in their names (`relative_volume`, `bollinger_bands`) were incorrectly parsed. For example, `relative_volume` was parsed as `indicator_name = 'relative'`.

**Fix:** Added special handling for compound names:
```python
if indicator_spec.startswith('bollinger_bands'):
    indicator_name = 'bollinger_bands'
elif indicator_spec.startswith('relative_volume'):
    indicator_name = 'relative_volume'
```

### 4. Breakout 20-Day High Included Current Bar (BUG)

**File:** `simulator/strategies/strategy_breakout.py`

**Problem:** The breakout calculation included the current bar in the 20-day high:
```python
# Bug: This includes current bar, so current > max always fails
high_20d = data['high'].iloc[-20:].max()
```

**Impact:** `current_high > high_20d` was always False because current high was included in the max.

**Fix:**
```python
# Fixed: Exclude current bar from the 20-day high
high_20d = data['high'].iloc[-21:-1].max()
```

### 5. Strategy Required Indicators Not Specific Enough

**Files:**
- `simulator/strategies/strategy_trend_following.py`
- `simulator/strategies/strategy_breakout.py`

**Problem:** Strategies requested generic indicator names like `ema` but accessed specific columns like `ema_20`, `ema_50`.

**Fix:** Updated `required_indicators` to be specific:
```python
# Trend Following
self.required_indicators = [
    'adx',
    'supertrend',
    f'ema_{self.ema_fast}',   # ema_20
    f'ema_{self.ema_slow}',   # ema_50
    'vwap'
]

# Breakout
self.required_indicators = [
    'adx',
    'atr',
    f'ema_{self.exit_ema_period}',  # ema_10
    'vwap',
    'relative_volume'
]
```

### 6. SPY Data Not Loaded in Offline Mode

**File:** `simulator/data_manager.py`

**Problem:** In offline mode, if there was a gap in data coverage, `get_stock_data()` returned None instead of available data.

**Impact:** SPY-relative strategies (500 Intersection, SP500 Slope v2) received `spy_data=None` and couldn't calculate relative strength.

**Fix:**
```python
if self.offline_mode:
    # Return whatever data is available instead of None
    available_data = self.load_offline_data(symbol)
    if available_data is not None and not available_data.empty:
        return available_data
```

## Root Cause Analysis

These bugs existed because:

1. **Indicator System Evolution:** The advanced indicators were added later but the pre-computation loop wasn't updated to handle them.

2. **String Parsing Edge Cases:** Indicator names with underscores weren't anticipated in the original parsing logic.

3. **Implicit Assumptions:** The breakout strategy assumed a particular behavior of the high_20d calculation that wasn't correct.

4. **Offline Mode Oversight:** The data manager prioritized data completeness over availability, which breaks offline testing.

---

## Recommendations

1. **Add Indicator Unit Tests:** Each indicator should have a test verifying correct column names are created.

2. **Strategy Validation:** Add a validation step that checks if required indicator columns exist in the data before generating signals.

3. **Defensive Coding:** Strategies should handle missing indicators gracefully with warnings rather than silent failures.

4. **Offline Mode Testing:** All features should be tested in offline mode to ensure they work without API access.
